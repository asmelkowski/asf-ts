# Core design and operational contract

This page describes the preserved code-authored runtime and observation map. Optional composition and authoring extensions use the same durable actions and accounting. Read the [TS port design](designs/ts-port.md), [typed children](designs/child-workflows.md), [profiles](designs/profiles.md), [portable files](designs/portable-files.md), [Studio](designs/studio.md), [declared inspection](designs/declared-inspection.md), and [candidate verification](designs/candidate-verification.md) for their current contracts. The v1 store gains additive workflow tables without rewriting historical receipts or ledger rows.

## File map

| File                                                              | Responsibility                                                                                             |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `src/types.ts`                                                    | Small `Harness`, request, sink, receipt, accounting, agent contracts                                       |
| `src/runtime.ts`                                                  | Run ownership, stable actions/scopes, raw/typed agents, correction, command composition                    |
| `src/store.ts`                                                    | Authoritative shared SQLite v1 store, reservations, immutable reports/ledger, session CAS, bounded queries |
| `src/accounting.ts`                                               | Explicit rate validation, normalized tokens, cumulative deltas, known subtotals                            |
| `src/adapters/{codex,opencode}.ts`                                | SDK-specific mapping and accounting scope                                                                  |
| `src/adapters/opencode-server.ts`                                 | Private authenticated loopback server handshake/lifetime, policy readiness                                 |
| `scripts/codex-launcher.mjs`, `scripts/opencode-policy/index.mjs` | Byte-only process lifecycle shim; native retry-policy hook                                                 |
| `src/process.ts`                                                  | Shell-free argv commands, bounded output, process-group cleanup                                            |
| `src/{cli,http,config}.ts`                                        | CLI/module loading, read-only localhost polling/SSE, explicit agent configuration                          |
| `src/web/*`                                                       | Legacy read-only inspector; Studio and declared graph extensions have separate linked designs              |
| `scripts/{ui-fixture,verify-ui}.ts`                               | Synthetic offline browser regression and Playwright video recording; no providers                          |
| `scripts/qualify.ts`                                              | Opt-in shared-budget live qualification; never invoked by checks                                           |
| `test/`                                                           | Runtime, shared adapter contract, injected exact SDK seams, real local process/HTTP/crash tests            |

The baseline module API needs no plugin discovery framework, orchestration service, provider pricing service, or separate application replay engine. Optional portable graphs lower to the same durable runtime. The tiny OpenCode policy module uses a vendor retry hook solely to decline retry-policy decisions. It does not control every vendor transport recovery path; see [the current source-check limits](sdk-upgrade-20260930.md).

## Authoring/API

Construct `Runtime({store, runId, workflowIdentity, cwd, live?, traceContent?, signal?, budget?})`, then `await runtime.run(async run => ...)`.

- `agent(id, config, {prompt, context?, session?, schema?, corrections?})` returns `{value,text,session}`. Raw value is a string; typed value is parsed JSON validated by Ajv in strict mode, without coercion/default insertion. Correction count is 0–3, default 0. Invalid output is never corrected after missing accounting, native failure, or truncation.
- An agent config is an ordinary reusable object containing `harness`, explicit `model`, optional `instructions`, `mode` (default read-only), and `timeoutMs` (default five minutes, maximum one hour). Adapter constructors snapshot caller-supplied pricing and operational options so later changes to those inputs cannot change execution behind the recorded identity. Construct a new harness to change them.
- Only explicitly selected JSON context enters the prompt. No implicit transcript concatenation.
- `command(id, argv, {timeoutMs?})` returns exit code, signal, bounded stdout/stderr, truncation, and cancellation. Nonzero exit is data for a negative branch. A timed-out command is retained and replayed as cancelled, not rerun.
- `scope(name)` prefixes action IDs; nest scopes or use `Promise.all` with independent sessions. Await every action. After a handled parallel rejection, draining siblings does not override the workflow's returned fallback; an uncaught workflow failure still aborts and drains. Catching a known validation failure and explicitly choosing a new repair action is allowed. Uncertain/incomplete accounting still blocks subsequent paid dispatch.
- Returned session handles belong only to the same run, adapter/provenance, model, workdir, and mode. Instructions may differ. Write mode is explicit. Concurrent continuation is rejected, including a baseline that advances during another call's preflight.

Workflow authors supply an identity that changes when relevant workflow code/dependencies change. The CLI hashes its entry module bytes, absolute path, input, config, and cwd; it does **not** hash imported dependency trees. Repeat the same CLI arguments on resume. Account-free replay does not require `--live`, but a new SDK send does. Work outside runtime actions executes again on resume; avoid untracked side effects.

## Storage and resume

One shared database, default `.asf/store.db`, holds runs, actions, invocations, sessions, reports, final ledger, budgets, and events. SQLite WAL + `synchronous=FULL`; Node's built-in SQLite is experimental in Node 22. No ORM or external database process. Schema `user_version=1`, unknown versions rejected. Historical v1 records remain intact. The extended runtime adds workflow tables without rewriting them; see [ADR 0212](adr/0212-local-actions-and-storage-compatibility.md).

1. Claim the run atomically using PID plus random owner token. A live PID blocks another executor, even after PID reuse. A dead PID can be reclaimed, but outstanding reservations become **uncertain**. Local machine only: do not share this store across hosts/NFS or PID namespaces.
2. Check stable action request identity: prompt/context/schema, config/protocol/policy binding, session handle, and bounds. A changed action is rejected before dispatch. Completed actions return stored results and emit only a replay observation.
3. Preflight known version/pricing failures. A definitely pre-reservation acknowledgement/preflight refusal leaves the action pending and emits bounded `action.blocked` metadata; the run still fails if the refusal escapes the workflow. An explicit later run with identical request identity may repeat non-model gates and send only the unreserved turn, including a pending correction after an earlier receipt. There is no automatic retry and no blanket clearing of failed actions: once reservation is attempted, failures remain conservative. Atomically reserve an invocation and any budget slot; lock the native session with a baseline comparison. Each correction is a separate reserved turn, not a retry of an earlier send.
4. Persist cumulative accounting observations directly, synchronously. Report keys deduplicate; conflicting duplicates fail. Keys over 256 UTF-8 bytes use a bounded prefix plus SHA-256 suffix consistently for lookup and insertion, rather than lossy clipping. Never put mandatory reports behind a content queue.
5. Local validation failures emit bounded reason/schema-hash/turn metadata (including the next correction turn when allowed), even if correction later succeeds. They do not relabel native success as native failure or retain prompt bodies. Atomically persist bounded raw receipt, final immutable ledger, and new native baseline **before** validation/action result commit. Resume can revalidate this receipt or perform the next bounded correction without repeating a completed send.
6. Missing receipt means no resend, even if the reservation might have preceded the actual send. Local setup/event-write failures after reservation use the same uncertainty path as transport exceptions. A transport exception keeps its strongest usable report as an incomplete lower bound. Native/validation failures keep raw receipts and usage. A successful native receipt without a new session baseline is retained/accounted but fails the action; an existing session stays locked. Incomplete reports or final ledger block new paid dispatches in that run/shared budget.

This is not exactly-once execution, external-state rollback, deterministic workflow replay, or automatic native receipt reconciliation. A crash after native completion but before ASF receipt persistence remains uncertain. There is no “retry anyway” switch. Inspect the records; investigate only with separate authorization. A new run/budget/database does not reconcile old liability and must not be used to bypass a qualification allowance. The SQLite database (and WAL while open) must be backed up consistently. Event history is observational; snapshot/receipt/ledger tables are authoritative.

Known failed-action replay preserves the original public error message (including an empty message); replay provenance is an observation, not a message prefix. Run completion means the workflow returned successfully, not that every command exited zero or that a caught failed action vanished. A durable receipt can exist even when its parent action/run failed. Sessions are ASF-exclusive: externally continuing one can contaminate cumulative baselines, especially Codex where the SDK cannot independently audit native history.

## Accounting

`Accounting` has status, nullable primary USD amount, kind (`billed`, `harness-estimated`, `asf-calculated`), model and whether observed/requested, scope/exclusions, source/version, normalized tokens, and explicit pricing. Current adapters produce **estimates only**. Additional non-overlapping auxiliary costs retain their own kind/model/source; unknown auxiliary prices stay null.

Reports are cumulative snapshots **within one invocation**, not additive line items. Failure recovery selects the strongest known subtotal including auxiliary amounts, never adds cumulative reports. Any mandatory incomplete observation remains unresolved even if a later or larger snapshot claims completeness; terminal reconciliation preserves that status before ledger commit and validation. Inspection run/budget unresolved counts also consider retained incomplete reports and uncertain invocations, including contradictory historical records whose immutable raw ledger remains unchanged. Complete accounting cannot contain unknown primary or additional amounts. Sum final ledger once per invocation, never reports plus ledger. `knownUsd` includes known primary/additional amounts only; `unresolved` must be considered with it. `costsByKind` keeps estimate/billed classifications separate. Commands have explicit zero **ASF-dispatched model** cost and are counted separately from model dispatches; arbitrary host commands can incur external costs outside ASF's knowledge.

Normal token convention: input excludes cache read/write; output includes reasoning. Reasoning is diagnostic, not charged again. Rates are USD per million tokens with explicit model, source and version. No catalog default, invoice equivalence, exchange-rate system, or unsupported-price fallback. `complete` means usable accounting for the declared **reported-token scope**, not proof that the provider emitted every billable request. See the adapter qualification document.

A budget uses a stable ID plus immutable max dispatches/soft USD threshold. Reservations consume the hard count before a send, including conservatively reserved turns that fail during later private-server/model preflight. Replays/host commands do not consume it. The USD threshold tests already-known subtotals, not in-flight work; it is **not a hard money cap**. Qualification processes should be serial: unresolved reservations from another process conservatively block the shared budget. An active parallel workflow can have multiple already-reserved in-flight sends.

## Bounds and observations

- Prompt/selected context: 64 KiB; schema: 16 KiB. Raw final text: UTF-8 prefix up to 64 KiB; truncated output never validates/corrects automatically.
- Runtime command output: 24 KiB per stream, retained prefix, drain continues. Raw receipts/action records have a 1 MiB serialized ceiling (JSON escaping can expand text).
- Mandatory accounting report: 16 KiB, at most 1,000 reports/invocation. Hitting a mandatory limit fails closed/incomplete, never silently drops charges.
- Trace: at most 500 normalized observations/invocation plus truncation marker. Strings/keys/collections/depth are projected and event payloads bounded below 8 KiB. Actual projection loss retains `projectionLoss: true` (or the overall `truncated` marker) across repeated projections; raw detail cannot restore discarded content. Older observations may lack these flags. Content off omits message/tool/reasoning bodies but retains required raw result/usage and model/lifecycle metadata. This is not a “store no sensitive content” option.
- OpenCode mandatory public-event observation: at most 5,000 unique events/invocation. Duplicate sequence entries are deduplicated; a contiguous sequence and final watermark barrier are required. Native log persistence is disabled by this CLI release (including its follow reader), so gaps fail closed. Content deltas from the public event feed use a separate lossy trace path; accounting is always processed.
- Event queries: max 200 rows/page; SSE polls batches of 100, monotonically increasing commit cursor, reconnect with last ID. `v=1`, run/action/invocation IDs, turn, fixed attempt 1 (no ASF retries; Codex may retry internally), source ID, and observation time. Commit order is not cross-agent causal order.
- HTTP readers never run inside provider drain callbacks. Backpressured clients stop fetching; stalled clients are disconnected after two seconds; at most 32 connections. The plain web UI renders retained content as text only, never HTML/Markdown or model-supplied resource URLs. HTTP inspection exposes bounded pages of sensitive results without authentication, only on loopback, no CORS, foreign Host/any Origin rejected. Explicit static assets have a restrictive CSP and deny framing. The UI uses same-origin GET polling, not browser EventSource (which can send the rejected Origin header); the SSE API is unchanged.
- The read-only execution map projects the current action/invocation pages into lanes by explicit slash-separated action-ID prefixes. Cards and turn buttons select the adjacent retained-content/accounting panel; dropdowns remain secondary navigation. Dashed session rails represent shared recorded membership only; turn numbers order turns within an action, not global execution or inferred dependencies. No timestamp-derived edges, parallel labels, fork/join nodes or timing intervals are fabricated. Card costs sum only loaded final ledger rows (including known auxiliary amounts), labelled visible/partial; missing and unresolved coverage is explicit. No persisted metadata, runtime graph or scheduling semantics are added. Exact causal edges would require future explicit author-provided metadata, not inference from observations. The pure page-local model is a classic allowlisted script (avoiding Origin-bearing module imports), checked with strict JSDoc alongside the UI. Desktop panels scroll independently; mobile stacks them. Map focus/selection survives polling and all DOM windows remain bounded.
- Each inspection response uses a short deferred read transaction for one SQLite snapshot, including on read-only connections. Event polling remains a separate cursor feed, not the same cross-endpoint snapshot. Shared inspection DTOs and a no-emit JSDoc/checkJs pass check the plain browser JS during `npm run typecheck`; assets are still copied unchanged and loaded only by `serve()`.
- UI run summaries use a bounded SELECT, newest `created` then `id` descending, with validated offset/limit (max 200); no storage/schema changes. The UI pages runs/actions/invocations at 20 each. The action and invocation pages are independent, not a complete per-action history. Event polling retains at most 100 loaded observations and pauses at a full batch for explicit paging, rather than auto-fetching unbounded historical events. Run switches abort requests/clear timers and reset the cursor/window; reconnects retain the cursor and deduplicate. Empty/unknown runs, absent receipts, nullable costs, exposed omission/truncation markers and loaded-window limits are explicit. Final ledger subtotals are not added to cumulative reports. The header caveat states that prompts are not retained, tracing defaults off and may drop/truncate, and receipts survive tracing off; this is not a complete terminal transcript or normalized chat. No dispatch/retry/edit controls or native-session file reads are provided.

These are ASF retention/queue limits, not universal process-memory or disk quotas. Official SDK parsers, vendor native stores and tool execution have their own buffering/storage behavior. Total store retention grows with runs; no automatic deletion is provided. Native session files may retain more content than ASF traces.

## Cancellation and safety

Runtime signals/timeouts reach SDK operations. Codex uses an invocation-owned cancellation signal: active cancellation is forwarded, then the upstream listener is detached when the SDK iterator is disposed. This prevents a later workflow/sibling abort from re-signalling a child whose v0.159.2 SDK error listeners have already been removed. Codex's official SDK parses exec JSONL; a byte-forwarding executable shim owns a process group and bounds stderr, sends TERM/KILL on abort, and monitors parent loss. It never parses provider JSONL. OpenCode uses `session.interrupt`, AbortSignals and final owned-server process-group cleanup. Local commands use argv without a shell, TERM then KILL, and do not wait indefinitely for descendants holding pipes. Tests exercise TERM-ignoring descendants and leader-exit pipe retention.

No rollback or sandbox stronger than the vendor is promised. Codex selects native read-only/workspace-write sandbox and no approvals. OpenCode's read-only policy denies shell/edit/subagent/network tools and permits read/glob/grep/list; it is a **permission policy, not an OS sandbox**. Write mode permits shell/edit and is not a security boundary around cwd. Escaped/detached processes and arbitrary trusted workflow code remain outside strict containment guarantees. Do not run hostile workflow modules, schemas, tools, or prompts with access to valuable files.

OpenCode's private native DB/config deliberately exclude ordinary global native credentials and sessions. A trusted caller may explicitly supply a provider-bound `apiKey` for a newly owned server; the official client provisions it after policy readiness, without placing its value in ASF identity, argv or inline config. Continuations reuse the owned DB and do not re-provision or import auth. There is no automatic credential discovery or global auth change. Native DBs now may retain credentials as well as session content; keep them private. Inherited provider environment variables can reach tools, so a sensitive caller should use an allowlisted environment. Credential-handoff exceptions withhold native details, but ASF makes no general secret-redaction guarantee.

## Adding a third adapter

Implement `Harness`: stable JSON `identity` including SDK/CLI/policy, non-model `preflight`, `invoke(request,sink)`, optional `close`. The caller owns reusable harness lifetime and must await its optional `close()` once it is no longer used; Runtime never closes a reusable harness after an action/run. Current adapters clean up invocation-scoped resources themselves; no automatic CLI close-hook lifecycle is introduced. Respect AbortSignal, return a bounded native final answer/session baseline, expose available normalized events, and synchronously report cumulative accounting independently of traces. Return incomplete/null when coverage is missing; never retry sends for usage. Accounting raw metadata must exclude transcript bodies. Native failure may preserve partial text/usage. Run the same raw/typed/correction/session/replay/accounting contract tests plus provider-specific usage/failure fixtures and local lifecycle tests. No registry or factory framework is needed.
